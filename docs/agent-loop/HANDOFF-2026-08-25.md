## ★ 1. TOMORROW MORNING, FIRST THING — did the corpus fix land?

**The biggest find of the session: a regex in `build_fts5.py` had been
deleting most of some judgments since 2026-02-22.**

`_HTML_TAG_RE` was `<[^>]+>`. `[^>]` matches newlines, so in OCR'd
historical text a single character misread as `<` swallowed everything to
the next `>` — thousands of chars, many lines — and left one space.
Measured against the source shards:

    bge_historical_14_I_192   12,159 -> 2,317 served   80.9% lost
    bge_historical_11_I_5     13,081 -> 6,585          49.7% lost
    bge_historical_15_I_79    13,004 -> 8,645          33.5% lost

Each file had 1-6 stray `<` and **no real HTML**. `"1<r"` is OCR for
`"1er"`. `_clean_text` runs over **full_text, regeste AND title**, so
headnotes were truncated too — the surface R2/R3 quotation rests on.

Fixed in `8e7eeb35` (`<[^>\n]{1,200}>`, 7 tests). **Deployed, but it only
takes effect when the builder next runs** — the 03:30 UTC build of 08-26.

```bash

    r=c.execute(\"SELECT length(full_text) FROM decisions WHERE decision_id=?\",(d,)).fetchone()
    print(d, r[0] if r else None)"'
```

**THEN (still unknown): size the blast radius.** We know 3 decisions;
we do not know if the population is hundreds or tens of thousands, nor
