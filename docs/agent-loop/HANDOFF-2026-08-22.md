## Incident: search 500s, 12:41–13:24 UTC (self-inflicted, resolved)

The `#89` weak-match helper shipped in `4f8c1cdd` was named `_term_coverage`.
That name was already bound at line 7173 by the search reranker's scoring
function, which `_rerank_rows` calls five times. Python keeps the last
definition, so from the 12:15 rolling restart every reranked search called a
function with the wrong signature. **458 tracebacks; `search_decisions` and
`/api/decisions?query=` returned 500.** Hotfix `4456f1c6` renamed the new one
to `_scholarship_term_coverage`; verified restored.

Three things to carry forward, in order of importance:

1. **No monitor would have caught it.** `quality/smoke.py` probed health, one
   decision page, one export and publish freshness — nothing that ran a query.
   It was found because a human ran `make smoke` by hand. Fixed in `7e641ec9`:
   there is now a `search_query` probe, and `publish_freshness` is build-aware
   (it had been red ~13h of every day, so it was *already* alarming during the
   outage and would have added no signal).
2. **The suite passed 2003 tests either way**, because nothing called
   `_rerank_rows` — the hottest path in the product had zero coverage.
   `tests/test_rerank_rows_smoke.py` now executes it;
   `tests/test_no_shadowed_definitions.py` catches the collision structurally.
   Both verified against a scratch copy carrying the real bug: 13 failures with
   it, 21 passes without.
3. **Two definitions 4,800 lines apart in a 22,000-line module are invisible to
   review.** The AST guard is the only thing that scales here. If `mcp_server.py`
   is ever split, keep that guard pointed at whatever replaces it.
