The Useful
Dataset Plan

A decision corpus becomes legal infrastructure when every row is complete, knows what it is, knows where it stands, and declares how much of the whole it represents. Everything below serves those four properties, for four audiences: lawyers, courts, researchers, and builders.

basis: 995,262 decisions · 118 courts · 8.65M resolved citation edges · 21,108 laws · ~2,000+ weekly assistant users · inputs: LegalStats upstream wishlist (verified 07-02) + deep-review backlog (07-01) + Tier-1 roadmap
01 / THE MODEL

Four properties, stacked

Each layer is only as useful as the one beneath it. Statistics on wrong dates mislead; an appeal graph over unstable IDs rots; honest coverage numbers are the licence to publish any statistic at all. The plan works bottom-up.

I

Trust

Fresh daily, text-true, typed dates, stable IDs, alerting that pages a human. The row is correct.

II

Structure

Proceeding type, branch, chamber, legal area, document form, section offsets. The row knows what it is.

III

Relation

Appeal chains, treatment graph, BGE linkage, resolved citations everywhere. The row knows where it stands.

IV

Honesty

Per-court coverage vs. portal totals, publication-practice notes, methodology. The row declares its denominator.

03 / RULES OF CONSTRUCTION

Principles

Raw text is sacred.R2 verbatim quotation depends on byte-true text. Cleaning (dehyphenation, normalization) ships as additional fields, never in place.
Build-side beats scraper-side.Docket codes, rubrums and citations are already in every row. Dictionaries and parsers at build time apply retroactively to 995k rows with zero scraper blast radius. Scraper changes only for data that exists solely at the portal (legal_area, filing_date, Streitwert).
NULL over guess.Every derived field carries its method; unknown stays NULL. Half-populated columns with drifting semantics (today's outcome, decision_type) are traps — fix the semantics or drop the column.
Denominators or it didn't happen.Every statistic the dataset enables must be pairable with "out of how many". Coverage metadata is a first-class product surface, not an internal health check.
One corpus, three doors.MCP (assistants), REST (apps), Parquet (bulk) expose the same fields with the same semantics. A field that exists in one door exists in all three.
Completeness remains paramount.Enrichment never trades away coverage; dedup never drops a legitimate decision. (Standing mission directive.)

07 / KNOWN RISKS

Risks & their answers

  • Taxonomy overreachForcing 26 cantonal procedural vocabularies into one enum invites wrong labels. Answer: NULL over guess; per-court dictionary entries reviewed against samples; version the dictionary.
    structure
  • Derived-field driftBuild-side derivations can silently rot as courts change code schemes. Answer: QC checks per derived field (coverage % per court, week-over-week drift).
    trust
  • Coverage table misread as quality scoreLow publication rates are court practice, not scraper failure. Answer: the note column + methodology page distinguish "not published" from "not captured".
    honesty
  • Single maintainerThe plan is sequenced so every phase leaves the dataset strictly better even if the next never ships. No big-bang migrations; every field additive.
    meta
