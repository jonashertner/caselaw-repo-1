OpenCaseLaw · Completeness + Pipeline Design

Recovering 7,052 garbled ge_gerichte decisions by OCR — and unblocking the cutover

The incremental‑cutover blocker turned out to be a data‑quality defect, not a build mechanism: thousands of Geneva PDFs use CID‑encoded fonts with no Unicode map, so the scraper stored binary garbage. Neither re‑extraction nor an es copy can fix it — but OCR recovers clean text, proven end‑to‑end.

2026‑07‑01 · supersedes the dedup‑truncation draft root cause + recovery PROVEN gated · shard write + multi‑hour OCR

TL;DR. ~7,052 ge_gerichte decisions (4.2% of the court) have full_text that is 58% C0 control characters — a failed extraction of CID‑encoded PDFs (no ToUnicode CMap). fitz yields glyph‑byte garbage; pdfplumber yields (cid:N) placeholders; 0 have an entscheidsuche fallback. OCR (tesseract fra) recovers clean text — verified. The "structure drift" blocking the cutover was the full builder mining false Erwägungen from this garbage while the incremental (cleaned text) correctly found none. Fix: OCR‑backfill the 7,052 → search recall + structure recover, and the ge half of the drift closes. A separate, smaller ne/ti/so es‑vs‑direct structure nuance (~3,600, text is fine) is handled last.

The PDFs embed custom fonts whose glyph IDs are not mapped to Unicode, so any text‑layer extraction fails; OCR reads the rendered glyphs as images and bypasses the encoding entirely. The PDFs are fetchable from Hetzner and tesseract‑fra is installed.

CID font, no ToUnicode→ scraper stores garbage→ decisions.db serves garbage→ 0 structure + broken search→ full builder mines FALSE structure → drift

03Plan

Phase 1 · completeness (primary)

OCR‑backfill the 7,052 garbled ge_gerichte decisions

backfill_ge_ocr.py (written, sample‑validated): for each garbled row → fetch pdf_url → render pages (fitz) → OCR (fra) → normalize → clean full_text.

  1. Sample (no shard write): 20 decisions → scratch file; review recovered‑text quality + length/control deltas. ← we are here.
  2. Full run (gated): all 7,052, parallel across the 16 cores; writes a NEW ge_gerichte.jsonl.ocr with a resumable checkpoint — never edits the live shard in place. Mark rows text_source:"ocr" for idempotency.
  3. Operator reviews counts + a sample, then swaps .ocr → live shard. Next nightly rebuild ingests clean text.
  4. Verify: search recall on a recovered docket; get_decision_structure now returns real Erwägungen.
Phase 2 · cutover

Close the structure drift, flip to daily‑incremental + Sunday‑full

  1. With ge text clean, both builders extract real structure from the same text → the ge half of the drift disappears.
  2. Stop the full structure builder mining raw shards for the remaining garbled tail (point it at cleaned decisions.db, or down‑weight false positives) so the gate compares like with like.
  3. 7 green shadow nights → flip publish.timer to Sunday‑only; promote the incremental to serving Mon–Sat.
Phase 3 · the es‑structure tail

ne/ti/so: prefer the better‑parsed copy

~3,600 decisions where dedup kept the longer direct copy but the es copy parses more Erwägungen. Smallest, lowest‑risk: bias the structure build toward the copy that yields more structure for the same decision, or re‑run extraction on both and keep the richer parse. Independent of the cutover; do after Phase 1–2.
