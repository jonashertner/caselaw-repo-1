# OpenCaseLaw Decision Profile — v0.1 (DRAFT)

**Status**: Draft, 2026-04-30. Open for comment.
**Editors**: OpenCaseLaw — Independent project, Zurich
**Contact**: team@jonashertner.com

A profile for representing Swiss court decisions as structured, machine-readable data. **Not a new schema.** A profile of four existing standards, defining how to combine them for Swiss judicial output.

---

## Why a profile, not a new schema

Swiss courts publish decisions in 27 different ways (federal + 26 cantons). Most are PDF + a per-court HTML index. Cross-court analytics are hard, AI ingestion is brittle, citation linking is unreliable. The temptation is to design a Swiss-specific XML/JSON schema and lobby for adoption — but new schemas compete poorly with existing ones (XHTML 2.0, SOAP, RDF/XML are dead; their replacements are pre-existing standards). 

This profile takes the opposite approach: **use what already exists, define how to combine it for Swiss decisions.**

## Four-layer architecture

| Layer | Standard | Used for |
|---|---|---|
| Identity | **ECLI** (European Case Law Identifier) | unique, stable IDs |
| Metadata | **Schema.org/LegalCase** + JSON-LD | court, date, regeste, citations, statutes |
| Structural document (optional) | **Akoma Ntoso XML** (LegalDocML.eu) | full decision with sections, paragraphs, footnotes, inline cites |
| Human prose (optional) | **Markdown** | rendering-ready text |

Each layer is independent. A consumer that only wants metadata reads JSON-LD; one needing full structural markup reads Akoma Ntoso; one displaying to humans renders Markdown.

## Layer 1 — Identity (ECLI)

Every decision in the profile has an ECLI. For Swiss federal courts these are official; for cantonal courts we synthesize a conformant ECLI from court code, year, and docket. Format:

```
ECLI:CH:{COURT}:{YEAR}:{DOCKET_NORMALIZED}

Examples
ECLI:CH:BGer:2024:6B_1234.2024.1
ECLI:CH:BVGer:2024:A-1234.2024
ECLI:CH:OG-ZH:2024:LB210032        (synthesized for cantonal)
```

Court codes follow the Swiss `ecli.bger.ch` registry where official; otherwise OpenCaseLaw assigns short codes (documented in `courts.json`).

## Layer 2 — Metadata (JSON-LD with Schema.org/LegalCase)

Required fields for every decision:

| Field | Type | Source |
|---|---|---|
| `@context` | URL list | Schema.org + opencaselaw.ch profile |
| `@type` | string | `"LegalCase"` |
| `ecli` | string | layer 1 |
| `name` | string | court + docket + date (human-readable title) |
| `court` | object | `{"@type": "Court", "name": ..., "jurisdiction": "CH" or canton}` |
| `docketNumber` | string | original docket as published |
| `dateDecided` | ISO 8601 date | decision date |
| `inLanguage` | string | BCP 47 (`de`, `fr`, `it`, `rm`) |
| `url` | URL | canonical URL on OpenCaseLaw |

Recommended fields:

| Field | Type | Notes |
|---|---|---|
| `regeste` | string | official headnote, where published |
| `dispositiv` | string | operative part / holding |
| `legalArea` | string | Mietrecht, Strafrecht, etc. |
| `cites` | array of `{"@id": ECLI}` | resolved citations to other cases |
| `legislationCited` | array of URLs | Fedlex ELI references |
| `chamber` | string | court chamber/division |

Swiss-specific extensions (in `opencaselaw.ch` namespace):

| Field | Notes |
|---|---|
| `ocl:sachverhalt` | facts section |
| `ocl:erwaegungenByNumber` | object mapping E-number → paragraph text (preserves verbatim citation units like E.2.2.1) |
| `ocl:materialien` | references to Federal Council Botschaft (legislative intent) |

## Layer 3 — Structural document (Akoma Ntoso, optional)

For consumers needing full structural markup (legal NLP research, automated cross-referencing, complete fidelity), the profile recommends Akoma Ntoso XML (OASIS LegalDocML.eu). One file per decision; URL referenced from the JSON-LD `ocl:akomaNtoso` field.

OpenCaseLaw will publish Akoma Ntoso for the BGer subset first (highest-value, cleanest existing structure). Cantonal coverage will follow as parsing matures.

## Layer 4 — Human prose (Markdown, optional)

For rendering, the profile uses Markdown. Section headings (`## Sachverhalt`, `## Erwägungen`, `## Dispositiv`), inline citations as Markdown links to ECLIs, footnotes as Markdown footnotes. URL referenced from JSON-LD `ocl:markdown` field.

```json
{
  "@context": [
    "https://schema.org",
    "https://opencaselaw.ch/schema/v0.1.jsonld"
  ],
  "@type": "LegalCase",
  "ecli": "ECLI:CH:BGer:2014:5A_500.2013.1",
  "name": "BGer 5A_500/2013 vom 15. Januar 2014",
  "court": {
    "@type": "Court",
    "name": "Bundesgericht",
    "jurisdiction": "CH"
  },
  "docketNumber": "5A_500/2013",
  "dateDecided": "2014-01-15",
  "inLanguage": "de",
  "url": "https://mcp.opencaselaw.ch/entscheid/bge_140_iii_86",
  "regeste": "Art. 41 OR; Tierhalterhaftung. Die Halter... [official headnote]",
  "dispositiv": "Die Beschwerde wird abgewiesen.",
  "legalArea": "Haftpflichtrecht",
  "chamber": "II. zivilrechtliche Abteilung",
  "cites": [
    {"@id": "ECLI:CH:BGer:2010:9C_500.2010.1"},
    {"@id": "ECLI:CH:BGer:2007:5C_120.2007.1"}
  ],
  "legislationCited": [
    "https://www.fedlex.admin.ch/eli/cc/27/317_321_377/de/art_41",
    "https://www.fedlex.admin.ch/eli/cc/27/317_321_377/de/art_56"
  ],
  "ocl:sachverhalt": "[facts section text]",
  "ocl:erwaegungenByNumber": {
    "1": "[paragraph 1 text]",
    "2.1": "[paragraph 2.1 text]",
    "2.2": "[paragraph 2.2 text]"
  },
  "ocl:materialien": [
    {
      "@id": "https://www.bj.admin.ch/dam/bj/de/data/wirtschaft/gesetzgebung/aktienrecht/botschaft.pdf",

    }
  ],
  "ocl:akomaNtoso": "https://opencaselaw.ch/data/akn/bge_140_iii_86.xml",
  "ocl:markdown": "https://opencaselaw.ch/data/md/bge_140_iii_86.md"
}
```

## Versioning

Profile versions are SemVer-style major.minor:
- v0.x = draft, breaking changes possible
- v1.0 = stable, breaking changes only at major
- minor versions add fields without breaking existing consumers

`@context` URL pins the version: `https://opencaselaw.ch/schema/v1.jsonld` for stable v1.

## Open questions

1. **Court code registry**: should we use ecli.bger.ch's official codes for federal + assign our own for cantonal? Or wait for an official cantonal registry?
2. **Materialien linking**: Botschaft refs are non-trivial. Use Fedlex URLs where present, else free-text?
3. **Multilingual decisions**: some decisions exist in DE+FR+IT. Single ECLI with language-tagged fields, or one ECLI per language?
4. **Erwägungen numbering**: existing E-number conventions vary across courts. Profile mandates the verbatim Swiss-citation form (e.g. "2.2.1") rather than re-numbering.
5. **PDFs**: are they part of the profile or excluded? Suggest excluded — Markdown + Akoma Ntoso make PDFs redundant.
